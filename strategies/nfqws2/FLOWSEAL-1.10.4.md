# Flowseal 1.10.4 — NFQWS2 для Netcraze/Keenetic, по вашему образцу

Этот комплект заменяет ранее выданный универсальный комплект 1.10.4. Здесь 22 конфигурации в формате присланного nfqws2.conf: отдельные NFQWS_BASE_ARGS, NFQWS_ARGS, NFQWS_ARGS_QUIC, NFQWS_ARGS_UDP, MODE_LIST/ALL/AUTO, NFQWS_EXTRA_ARGS, NFQWS_ARGS_IPSET, NFQWS_ARGS_CUSTOM и служебные настройки. Новый запускатель или новая служба не требуются.

## Что сохранено из вашего файла

- ISP_INTERFACE="eth3", IPV6_ENABLED=0, POLICY_NAME="nfqws", POLICY_EXCLUDE=0.
- NFQUEUE_NUM=300, USER=nobody, CONFIG_VERSION=1 и настройки журнала.
- По умолчанию NFQWS_EXTRA_ARGS="$MODE_ALL".
- TCP/UDP-порты из образца, включая 853 для DNS.
- Три пользовательских DNS-профиля, их домены, IP-адреса, методы и числовые параметры.
- Подключение zapret-lib.lua, zapret-antidpi.lua и zapret-auto.lua.

В присланном тексте имя blob `tls_clienthello` использовалось, но не объявлялось. Оно явно привязано к tls_clienthello_www_google_com.bin. Это выбранное исправление отсутствующей ссылки, а не установленное значение из вашей старой среды. Строка `#DNS` удалена из значения NFQWS_ARGS_CUSTOM: внутри двойных кавычек это не shell-комментарий, а часть строки аргументов.

## Что взято из Flowseal 1.10.4

Все 22 стратегии и цепочки обработки всех 195 профилей сохранены, включая отключённые игровые профили. Repeats, split-pos, seqovl, cutoff, fooling, порядок нескольких fake и выбор blobs не смягчались. В частности, изменённые вручную в вашем примере aliases discord_udp/game_udp не использованы как замена исходным файлам Flowseal. Для Discord/game применяются именно файлы, указанные в соответствующих BAT 1.10.4.

ALT5 имеет особую структуру: в исходнике нет отдельного Google TCP и Discord-media TCP; его общий IPv4 syndata,multidisorder сохранён. ALT7 сохраняет отличающийся IP TCP-профиль syndata. EXP сохраняет свой QUIC-профиль без ограничения порта и его приоритет перед Discord UDP.

## Важное отличие от образца: IP-профили

NFQWS_ARGS_IPSET оставлен пустым. Это отключает автоматическое копирование общей HTTP(S)/QUIC-стратегии службой. Вместо него в CUSTOM явно сохранены исходные IP-профили со своими списками, исключениями и методами. Так сохраняется отдельная обработка 8443, ALT7 и дополнительных исключений EXP.

Поскольку служба ставит CUSTOM раньше основных переменных, IP TCP разбит на 8443 и 80/443. В раннем IP-профиле 80/443 исключены user.list, user-extra.list и rkn.list, чтобы домены основного списка не потеряли приоритет своей HTTP(S)-стратегии. Google и Discord-media остаются раньше IP-профилей. Три DNS-профиля пользователя идут перед IP-профилями.

Это адаптация к режиму вашего образца: MODE_ALL расширяет область общего профиля относительно исходных BAT с hostlist. IPv6, наоборот, выключен по вашему образцу. Сохранение методов и числовых параметров не означает побайтово одинаковую область применения с Windows-версией.

## Как использовать

1. Сохраните копию текущего /opt/etc/nfqws2/nfqws2.conf и своих списков.
2. Добавьте файлы из blobs/ в /opt/etc/nfqws2/blobs/.
3. Проверьте версию NFQWS2 и совместимость Lua. Библиотеки в lua/ взяты из официального zapret2 v1.0.7, Lua API 6. Они должны соответствовать версии установленного движка. Не заменяйте библиотеки другой версии вслепую. Для стратегий с altorder=1 нужен также flowseal-compat.lua из комплекта.
4. Файлы lists/ соответствуют именам вашего образца. Не заменяйте существующие пользовательские rkn.list, auto.list, user.list и исключения пустыми/типовыми файлами. Добавьте недостающие файлы; домены из комплектных user.list/google.list при необходимости объедините со своими без удаления своих записей. В rkn.list и auto.list комплект не добавляет данных: их содержимое не было предоставлено.
5. Выберите один файл из configs/, например alt12.conf, и сохраните его как /opt/etc/nfqws2/nfqws2.conf. Не запускайте все стратегии одновременно.
6. Выполните проверки ниже, затем перезапустите существующую службу NFQWS2 обычным для вашей установки способом.

Комплект не содержит нового run.sh и не меняет firewall/службу самостоятельно. ISP_INTERFACE и политика уже выставлены по вашему образцу.

## Проверка на устройстве

Из папки, куда распакован архив:

```sh
sh verification/check-on-device.sh /opt/etc/nfqws2/nfqws2.conf --dry-run
sh verification/check-on-device.sh /opt/etc/nfqws2/nfqws2.conf --intercept=0
```

Если бинарник не найден, задайте NFQWS2_BIN=/opt/sbin/nfqws2 перед командой. Первая проверка проверяет параметры и доступность файлов, вторая — инициализацию Lua без перехвата. Порядок аргументов в проверке: BASE, CUSTOM, UDP, QUIC + EXTRA, HTTP(S) + EXTRA. Фактически установленная версия службы не была доступна для чтения, поэтому её реализацию запуска здесь не проверяли.

## Game Filter

В вашем образце он выключен. Здесь также выключен; никакие игровые порты автоматически не добавляются. Полные исходные игровые профили каждой стратегии находятся в game-profiles/*.args. Их повторы, fake, диапазоны и cutoff сохранены; исходный включённый диапазон — 1024-65535.

Для включения требуется поддержка добавления этих профилей ПОСЛЕ основных профилей в итоговой командной строке и соответствующие правила перехвата портов. Не вставляйте полный диапазон в начало CUSTOM: это изменит приоритет Google/основного TCP/QUIC/Discord. Фрагменты не являются самостоятельными конфигами запуска.

## Проверки и ограничения

- Все 22 .conf проверены настоящей shell-командой sh -n.
- Каждый .conf загружен оболочкой; сформированы аргументы запуска по структуре службы. Проверены служебные настройки, отсутствие случайных #DNS/лишних слов и пустых профилей.
- Во всех обычных группах отсутствует --new; разделители используются только в CUSTOM.
- Все 195 исходных последовательностей Lua-вызовов, payload и out-range найдены без изменения в основных, дополнительных или игровых профилях результата.
- Все ссылки на списки и blobs разрешаются; исходные blobs побайтово сохранены.
- Все четыре Lua-файла скомпилированы LuaJIT 2.1. Совместимость altorder=1 ранее проверена синтетическим тестом порядка частей.
- Родной Linux NFQWS2 --dry-run и работа на вашем Netcraze/сети не проверены. Это не обещание отсутствия задержек YouTube.
- Отличия реализации сегментации, MSS, IP ID, TLS без SNI и случайных TLS-полей между winws1 и NFQWS2 остаются. Для multidisorder используется multidisorder_legacy.

verification/results.json содержит результаты проверок, verification/profile-map.json — распределение профилей. source-lists/ содержит неизменённые списки предыдущего переноса 1.10.4 для сверки. SHA256SUMS позволяет проверить целостность комплекта.
